## Open StudBud

After the GitHub Pages deployment finishes, open **https://mystudbud.org/** in Chrome, Safari, Edge, or Firefox. The site works on phones, tablets, Chromebooks, and computers without installing anything.

On Chrome for desktop, use the install icon in the address bar or choose **Install StudBud** from the browser menu. On Android, open the site in Chrome and choose **Add to Home screen**. On iPhone or iPad, open it in Safari and choose **Share → Add to Home Screen**.

The app shell is cached for offline loading after the first visit. Internet access is needed for account sign-in and syncing, externally hosted fonts and icons, and chart libraries.

If account connection settings fail to load, startup retries their script once. The sign-in screen then offers **Retry sign-in connection** without requiring a page reload; guest access remains available. A successful retry clears the warning and re-enables account forms. Run `node tests/cloud-config.cjs` for startup recovery, failure, retry and timeout checks.

The Planner separates assignment priorities/workload from a Study section for quiz/test preparation and suggested sessions. Quizzes and tests have their own editable records table, including completed/graded assessments; search, class and status filters apply to both records tables. Study suggestions update after logging sessions or changing linked flashcards.

Calendar days show separate assignment, quiz/test and personal-event counts. Each day's agenda separates those categories from the class schedule. Use **Add assignment**, **Add quiz / test**, or **Add event** for the selected day. Personal events support a title, date, optional time and notes, with editing and confirmed deletion; they do not affect assignment workload or grades. Events save locally and are included in account-sync snapshots and backups.

## Ads

Optional, non-sticky banner slots sit at the bottom of Home, the decks list, and the shop. They stay collapsed until configured and are hidden offline, during tutorials, study sessions, games, and dialogs. There are no interstitials, rewarded ads, videos, or automatic refreshes.

Use manual horizontal units and keep AdSense Auto ads, anchor ads and vignette ads disabled in the AdSense account. Account-level automatic formats would bypass these footer-only placement rules.

In `ads.js`, fill in `window.STUDBUD_ADS.client` with your AdSense publisher ID (`ca-pub-XXXXXXXXXXXXXXXX`) and `slots.home`, `slots.decks`, and/or `slots.shop` with the corresponding ad-unit slot IDs. Leave any unused slot empty. The Google script loads only when a configured banner enters the viewport. Use `window.StudBudAds.refresh()` after changing configuration at runtime. Ad blockers or network errors leave the app usable.

Replace the commented example in `ads.txt` with your AdSense-authorized seller line and publish it at the **domain root** (for project-path hosting, this may require the root Pages repository or a custom domain). Follow AdSense approval, privacy/consent, and child-directed-content requirements before enabling ads; this integration does not supply a consent-management platform.

## Accounts and cloud sync

New assignments default their due date to today in your local time zone. You can type in the date field or use its single built-in calendar icon. Adding from a calendar day keeps that selected day; editing an assignment preserves its saved date. Save & add another keeps your chosen date for quick batch entry.

StudBud uses Supabase Auth for username/password accounts and stores each account's synced app snapshot (classes, assignments, grades, schedules, flashcards, study history, and UI preferences) in a row protected by Row Level Security. Passwords must be at least 8 characters. Usernames are unique, case-insensitive, and limited to 3–24 letters, numbers, or underscores.

To connect the deployed static site to a Supabase project:

1. Create a Supabase project and run [`supabase-setup.sql`](./supabase-setup.sql) in the Supabase SQL editor as the default `postgres` role. Username uniqueness uses an RLS-protected app-owned claims table maintained by the auth trigger, not an index on Supabase's managed `auth.users` table. If an older script failed with `42501: must be owner of table users`, rerun the full updated script; do not change ownership of the auth table. Existing case-insensitive duplicate usernames must be resolved before the claims backfill can succeed; the script does not silently discard duplicates.
   **End of beta:** on the existing project, also run [`beta-reset.sql`](./beta-reset.sql) once, after the setup script. It resets every account's study time, streaks, XP and level, coins (back to 100), cosmetics and daily rewards. Accounts, courses, grades, flashcard decks, friends, classes and game wins are kept. Rerunning it does nothing. The app also drops study sessions from before 2026-10-15 on every device.
2. Enable password authentication with an 8-character minimum. Keep TOTP verification enabled while any existing account still has an enrolled authenticator.
3. Copy the project URL and **publishable/anon key** into `url` and `anonKey` in [`supabase-config.js`](./supabase-config.js). These are public browser credentials; never put a service-role key in this file.
4. In Supabase **Authentication → Sign In / Providers → Email**, keep the Email provider enabled and turn **off Confirm email**. This is the backend password provider for internal non-deliverable `@accounts.studbud.invalid` identifiers, not a user-facing email feature. Allow new signups if account creation is desired. No SMTP or email templates are needed by the app.
5. The setup records the existing `overit` and `andy` admin account UUIDs once, so access remains tied to account identity. For a new project, explicitly insert the intended admin's UUID into `public.studbud_admin_accounts` using the SQL editor; clients cannot edit that table.

Username-only accounts have no email-based password recovery. Do not put personal data in the public username. The frontend removal does not reconfigure the hosted Auth service or migrate previously email-linked accounts automatically.

The first account used on a device adopts any existing local StudBud data into its cloud account. After sign-out, the local app cache is cleared; if a different account is later used and has no cloud snapshot, it starts with a clean app rather than adopting the previous account's data. Signed-in changes sync automatically; sign in on another device to load the same account data. Manual backup export/import has been removed; normal sync and Infinite Campus imports remain available.

Cloud sync merges independent edits against the last saved baseline and retries concurrent server writes instead of replacing another device's changes. Pending local edits survive reload. Conflicting edits to the same field are reported explicitly with in-app choices to use cloud data or keep device data; neither version is overwritten before a choice is made. Sign-out waits for a successful save. Restoring decks, history and metrics uses one IndexedDB transaction so a failed restore does not partially clear those stores. Your own published decks are recovered automatically into your collection when opening your account.

**Question Chess** is a two-player real-time checkmate variant. Each correct question earns exactly **one move**, with at most one ready move held at once. There are **no regular alternating turns, energy settings, match timer or active-match expiry**: either player may move when ready, except that **only the checked player can move until escaping check**. Kings cannot be captured, and moving into check is illegal. Checkmate wins; stalemate or only kings remaining draws. Captured material starts at zero and uses standard values: pawn **1**, knight/bishop **3**, rook **5**, queen **9**. Winning is ranked separately from material points; draws do not select a material winner. Castling requires unmoved king/rook, clear squares and a safe king path. En passant is available immediately after the opponent's double pawn move, expiring on the next board move. Automatic queen promotion applies. The green-and-cream board uses one original, matching vector piece set for both colors and mode previews, with off-white and charcoal fills, dark outlines and subtle shading. Coordinates, last-move and check highlights, legal-move dots and capture rings clarify play. Piece movement animates unless reduced motion is enabled. A textured green gradient fills the game area, with responsive desktop, portrait and landscape layouts below the HUD. Keyboard/tap selection and mouse/touch drag moves are supported. Canceling an invalid drag preserves its credit. Solo practice has one simulated opponent.

The host serializes chess requests, validates moves against the current board and persists revisioned snapshots. A simultaneous move based on an older board is rejected without spending its credit. Repeated network requests are acknowledged only once; guests accept board snapshots only from the host and ignore older revisions. The host must remain connected; failed persistence or missing host acknowledgements are explicitly reported. Explicitly leaving ends a live chess room; finished rooms return to normal cleanup expiry. **Rerun the full updated [`supabase-setup.sql`](./supabase-setup.sql)** to enable the chess mode, two-player room limit, untimed rules, host-only board persistence and public study-set references in game review.

The top of the dashboard has a **Today at a glance** card: your streak, this week, today's goal, the next assignments to work on, and your grades and GPA. Tap **Customize** to choose which sections it shows and how many assignments to list. If you install StudBud, your current streak can also appear as a badge on the app icon (where supported), and long-pressing the icon offers shortcuts to your streak, planner and flashcards.

**Past credits:** Settings → Target Cumulative GPA has an optional **Past credits** section for credits and weighted/unweighted GPA earned in semesters you don't track in StudBud. When filled in, every cumulative GPA (dashboard, GPA page, projections, analytics history and the target-GPA plan) blends the past GPA with your tracked classes by credit weight. If only one past GPA is entered it is used for both; leaving credits blank or 0 turns blending off. Run `node tests/flashcard-space-prior-gpa.cjs` to check the blending and flashcard Space handling.

**Today's schedule** follows the school's weekday rotation and shows incomplete assignments, quizzes and tests due today under the matching class. Work for a class that does not meet today appears separately. Weekends and days with no matching classes explain that your schedule is still saved, offer **Edit schedule**, and include a collapsed preview of the next school day's classes.

### Administration

**Admin → Game testing** launches the seven main modes with infinite resources, zero to three simulated players and an optional reproducible map seed. Its collapsed **Tools** menu provides pause/resume, restart and live diagnostics. Test sessions do not award coins or change leaderboard records.

User and shared-deck moderation controls are collapsed until needed. Administrators can open public profiles, inspect every card in a shared set, see last sign-in and ban reasons, and use the existing protected moderation actions. **Announcements** publishes or unpublishes one site-wide message for signed-in students. Students can dismiss a message for the current page session; a new update makes it visible again.

Run the updated [`supabase-setup.sql`](./supabase-setup.sql) to enable full-deck inspection and announcements. These operations are administrator-checked on the server; the browser cannot grant access.

Only the latest active announcement appears in the banner until you dismiss it. Dismissal is saved to your account in Supabase and mirrored on the device after the save succeeds, so the same publication stays dismissed after reload, sign-in, or switching devices. Only publishing a new announcement creates a new banner; unpublishing does not reset dismissals or erase history. **Announcement history at the bottom of About** lists every archived publication chronologically newest first, including the current, dismissed and unpublished announcements. Each entry shows the publication date, time (in your local timezone), and publisher username; the newest entry is marked **Latest announcement**. The upgrade preserves the date/time and publisher of the currently stored announcement where available. An unavailable publisher is labeled **Site administrator**, not guessed. Saving a dismissal must succeed before the banner closes; any failure is shown so you can retry.

The publisher is captured from the authenticated administrator's account, not a hardcoded author list, so newly authorized admins are supported too. New announcements require a recorded username.

Rerun the full updated [`supabase-setup.sql`](./supabase-setup.sql) to install the announcement archive, author metadata and account dismissal functions. The upgrade archives the currently stored announcement once and preserves each future publication. Announcements overwritten before this upgrade cannot be recovered because the previous schema stored only one message.

Apply the latest `supabase-setup.sql` to enable account-backed multiplayer profiles, purchases, random drops, personal-best syncing, and hosted rooms.

If hosting a room or opening the shop says the feature is not enabled on the server, run the latest `supabase-setup.sql` in the Supabase SQL editor and reload StudBud. Multiplayer game rooms and shop purchases are handled by protected server functions and cannot be enabled from the browser alone.

The **Flashcard Importer** accepts tab-separated or other delimiter-separated term/definition rows without depending on a specific flashcard provider.

Supabase must be configured before account creation or sign-in is available. The GitHub Pages site is static, so this repository does not contain server secrets or a service-role key.

## Deployment

Every push to `main` automatically deploys the site to GitHub Pages using the workflow in `.github/workflows/pages.yml`. If a deployment does not start, open the repository's **Actions** tab, select **Deploy StudBud to GitHub Pages**, and choose **Run workflow** on `main`.
